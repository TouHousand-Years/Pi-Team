# Build lossless per-Run Transcripts

Type: wayfinder:task
Status: resolved
Blocked by: 02, 04

## Question

Implement and verify per-Run, append-only, unredacted process-boundary Transcripts before lossy semantic parsing, including submitted input, emitted stdout/stderr, ordering metadata, terminal and incomplete-capture state, seven-day/2-GiB cleanup, replay, backward-compatible registry reading, and worker isolation from storage failures.

## Answer

Implemented the Transcript v1 evidence layer under `src/transcript/` and wired it into the retained MCP core. Schema v1 (`schema.ts`) freezes the single-writer JSONL envelope: global `seq`, UTC + monotonic time, channel/kind, Base64 boundary-byte payloads chunked at 64 KiB with `groupId`/`part`/`final`, allowlisted launch metadata (submitted and effective prompts kept separate; no raw command line or environment), and a terminal record carrying outcome, exit/signal, timing, final sequence, byte counts, EOF, capture-error, Pi-settlement observation, and a SHA-256 over the exact serialized bytes preceding it. Terminal outcomes are `running`/`succeeded`/`failed`/`protocol-error`/`incomplete`, with the wrapper authoritative and Pi settlement events recorded only as cross-checks.

The writer (`writer.ts`) creates each bundle (`manifest.json` atomic, `lease.json`, append-only `transcript.jsonl`) before Pi spawns, buffers ordinary records at 250 ms/64 KiB, force-durable (fsync) boundary records, and never throws to the caller — every storage failure degrades into a capture-error state. The reader (`reader.ts`) replays losslessly: unknown/malformed/partial content stays visible and does not by itself damage integrity, while sequence gaps, terminal-hash mismatch, missing terminal, or a trailing unterminated line mark capture permanently incomplete. Crash recovery (`recovery.ts`) never adopts a Run: nonterminal bundles are reconciled only when the owning process is confirmed absent (or excluded as still-active), a trailing partial line is byte-preserved and terminated before the `incomplete` terminal is appended so the hash stays consistent, and ambiguity never triggers deletion or a kill. Retention (`store.ts`) implements seven-day/2-GiB cleanup over all inactive terminal bundles via atomic trash rename with purge grace, trash counting toward quota, oldest-first eviction, ownership checks on both the age and quota paths, and rename failure (the effective directory lock) skipping the bundle.

Runner integration: `spawn.ts` captures raw stdout/stderr bytes before decoding (StringDecoder for multibyte safety) and resolves collection on `close`/`exit`+grace so the lossless tail cannot be truncated by an early destroy. `delegate.ts` writes the bundle before spawn, records prompts, byte streams, session-establishment state, and settlement observation, downgrades capture integrity (never the wrapper outcome) when a stream errors, and maps registry status to Transcript terminal classes. `status.ts` exposes Transcript availability/outcome/capture integrity alongside the existing fields; `server.ts` schedules reconciliation+cleanup at startup and every 15 minutes, always excluding live Runs. Registry v1 reading is unchanged and runs without Transcript storage keep working. Verification: 21 new tests in `test/transcript.test.ts` covering byte fidelity (multibyte, binary, 64 KiB chunking), all terminal classes, capture-failure isolation, replay integrity (gaps, tampering, missing terminal, partial tails, malformed lines), recovery (dead owner, ambiguous owner, active-run exclusion, partial-tail consistency), cleanup (expiry, quota, ownership, trash purge, Windows rename-lock race), a 50,000-record replay load, and the two-tool surface regression; full suite 119/119, build passes. The formatted viewer, notifications, and `viewer-state.json` remain ticket 07.
