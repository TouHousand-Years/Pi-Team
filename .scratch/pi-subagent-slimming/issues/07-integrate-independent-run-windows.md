# Integrate independent Run Windows

Type: wayfinder:task
Status: resolved
Blocked by: 03, 06

## Question

Turn the accepted viewer prototype into the optional production Run Window integration: automatically launch one independent read-only formatted window for every sync or async Run, preserve full content and responsiveness, keep capture/notification alive after window closure, leave completed windows open, and ensure GUI failures never affect execution.

## Answer

`pi_delegate` now opens one independent read-only Run Window per Run — sync or async — and `pi_status` can reopen it. Three pieces carry the accepted design:

**The window** — `viewer/run-window.ps1` (separately shipped, Windows-only, pure ASCII so Windows PowerShell 5.1 cannot mangle it). One process hosts exactly one Run. It replays `<bundle>/transcript.jsonl` and tails it, reassembling raw byte groups (`groupId`/`part`/`final`) *before* decoding, so a character split across chunks or a 64-KiB boundary renders intact; invalid UTF-8 is shown as a lossless hex escape rather than U+FFFD. Display is formatted-only: streaming fragments are withheld while the Run is healthy and reconciled into their complete `*_end` event, `tool_execution_update` is withheld only when the final result actually covers it, and everything unrecognised, malformed, of a foreign schema version, or otherwise unmatched stays visible through explicit fallbacks. Conversation-level dedup follows the researched Pi 0.85.1 surface (message_update deltas → `text_end`/`thinking_end`/`toolcall_end`, usage only at `message_end`, `turn_end`/`agent_end` as structural markers), so each payload prints exactly once with no raw-JSON second copy and no summaries.

**The evidence check** — every file line read before the terminal record is hashed exactly as it appears on disk and compared with the terminal record's `sha256`. Sequence gaps, an unterminated stream line, an unterminated journal line, an incomplete byte group, a capture error, a foreign version and a short/absent terminal all mark the window `INCOMPLETE`; the underlying outcome stays visible in the status bar. Nothing is ever silently repaired.

**The launcher** — `src/viewer/manager.ts` + `state.ts`. Node spawns `powershell.exe -NoProfile -NonInteractive -STA -ExecutionPolicy Bypass -File <script> -BundleDir <dir>` with an argument array and no shell interpolation, then waits at most two seconds for the viewer's `ready` handshake in `viewer-state.json`. A live instance is raised via a `viewer-request.json` focus request instead of being duplicated — including an instance that is still starting; a replacement is launched only once the prior instance is confirmed gone. Reopening never redispatches work and never replays sound.

Sequencing inside `delegate` is the locked one: the bundle and its `launch` + `starting` records are durable first, then the window, then Pi. `pi_status` gained `openWindow`, `timing`, the Transcript's terminal timing plus Pi-settlement observation (read from a bounded file tail, never a full replay), and a `viewer` description. Every GUI failure mode — non-Windows platform, missing script, `PI_SUBAGENT_VIEWER=off`, spawn error, handshake timeout, viewer crash, a viewer that throws — returns a description and lets the Run proceed untouched; no window is opened at all when there is no usable evidence (storage disabled or bundle init failed).

## Comments

- `npm run build` and `npm test` pass: **154 tests, 0 failures** (baseline was 119). Tests were added, none relaxed; `test/mcp-surface.test.ts` now sets `PI_SUBAGENT_VIEWER=off` so the suite never opens a real window.
- Formatter matrix — `test/viewer-format.test.ts` drives the **real** PowerShell viewer headlessly (`-Replay`) against Transcript v1 bundles written in the exact on-disk format: healthy lifecycle with hash verification and per-payload-once proofs; all four terminal classes; capture error + sequence gap; byte-group reassembly across a split multibyte character plus an unterminated group; unknown/malformed/foreign-version losslessness; uncovered vs covered tool updates (text and non-text); a message that exists only in `agent_end`; an unterminated line pending while running and reported once terminal; bundle release after a terminal Run; a 2,004-record Run rendering every record exactly once; and `-SelfTest` (40,053-character Unicode round-trip, font-run mapping, glyph coverage, formatter honesty).
- Launch/containment — `test/viewer.test.ts` substitutes a stand-in viewer for PowerShell and covers the real `ViewerManager`: STA/shell-free argv construction, ready handshake, focus-instead-of-duplicate, reuse of a still-starting instance, replacement only after the prior instance is confirmed gone, a viewer that dies before handshake (reported immediately, not after the full budget), a viewer that never reports ready (bounded), launch/unavailable/throw isolation, `openWindow`, and the delegate ordering proof (bundle present, `pi-spawned` absent at open time).
- Real end-to-end verification (not just unit seams): a real `pi_delegate` through `ViewerManager` opened a real window (`viewer-state.json` `ready`, live pid, window title `[SUCCEEDED] Pi — smoke — Run the echo command. — run-smoke-0001`), the focus request was consumed, and renaming the bundle directory succeeded — proving the completed window released its files instead of pinning them. A separate live run appended the terminal record to a growing transcript and the open window moved to `SUCCEEDED` with `alertAttemptedAt` recorded, confirming tailing, terminal classification and the one-shot sound bookkeeping in the production path.
- Two review-driven corrections are worth naming, because they were real: (1) an alive instance that had not yet reported `ready` was not treated as live, so a reopen could race a second window into existence — now any live instance is focused and waited for; (2) the formatter confirmed `agent_end.messages` were redundant only by integrity state rather than by counting rendered assistant messages, so a message present only in `agent_end` could be lost on an otherwise clean stream — recovery is now gated on the message count and fires whenever a message is unaccounted for.
- **Pending, not done here:** human visual inspection of the *production* window (glyph appearance, formatted-only display, full titles, mid-stream close continuity, terminal status colours). Ticket 03 accepted these for the prototype and this implementation was machine-verified plus functionally exercised, but per the map a human must confirm the visual result. Also still pending: the audible/visual confirmation that the system sound actually plays (the *attempt* and its durable `alertAttemptedAt` guard are verified), real Pi 0.85.1 qualification, and the retention-while-open race — all belong to ticket 09's qualification.
- **Honest limits:** the window is a child of the MCP server, so it lives exactly as long as the server does; `DETACHED_PROCESS` cannot be used because Windows PowerShell (a console host) exits silently under it, and the design forbids shell-mediated launches, so windows do not survive an MCP-server exit. Within a server lifetime, a completed window stays open until closed by hand. The 50,000-record volume figure was proven at the prototype stage with the same batched RTF insertion path; the production viewer's automated volume check is 2,004 records (≈4 s), since the per-tick drain is deliberately time-budgeted.
