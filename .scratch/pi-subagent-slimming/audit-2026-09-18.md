## 未完成项与复现缺陷

### P1：已有会话续接未占用会话，允许同一 Pi Session 并发执行

位置：`src/tools/delegate.ts:150`、`:293`、`:310`。

续接时 `sessionIdReceived` 一开始为 true，而 `setRunning` 和 `incMsgCount` 只在 `!sessionIdReceived` 的新会话握手分支执行。因此第一条续接 Run 正在执行时 Session 仍为 idle，第二条同 Session 委派也被接受，绕过 `session_busy` 保护。探针实测：两次均返回 running，runningCount=2，Session 仍 idle。影响同一会话写入与状态一致性；续接计数也不更新。

### P1：未收到管道 EOF，500ms 强制收尾仍标记 sawEof=true

位置：`src/runner/spawn.ts:119`、`:132`。

`exit` 之后宽限到期会直接 `done()` 并 destroy 流；返回值仅检查 spawn/stream error，未确认 stdout 正常结束。探针保持 stdout 打开，只发 exit(0)，500ms 后仍收到 sawEof=true。若后代进程还持有管道、继续输出，尾部会被丢弃，但证据记录不能诚实反映未读到 EOF。当前哈希只能验证已记录的字节，无法证明丢失部分不存在。

### P2：运行中的纯轮询遗漏 Transcript 可用性/完整性

位置：`src/tools/status.ts:80`。

`waitTimeoutMs: 0` 的 running 分支直接返回，不调用 `transcripts.describe`。探针提供一个报告 unavailable/capture-error 的描述器，结果 describeCalls=0，响应不含 transcript。与 ticket 04 要求 status 返回捕获完整性和可用性不一致。该发现仅针对合法的纯轮询 API 分支；skill 的正常长轮询流程不应据此改成零等待轮询。
